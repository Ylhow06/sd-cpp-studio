# 技术说明

介绍本项目的技术选型与实现权衡。使用者只需要顺手的工具，不必关心这些；
**改代码 / 加功能 / 排查问题**时才需要读这里，或去看[单文件 UI 协作指南](单文件UI协作指南.md)。

> 本项目 vibe coding 产出。这里记录的是「为什么这么设计」的决策依据，
> 供后续维护者（含 AI 协作）不重复踩坑。

---

## 1. 为什么选 sd-server 而不是 sd-cli

批量出图需要频繁调用，`app\runtime\` 里两个可执行文件对比过：

| | sd-cli.exe | sd-server + HTTP（本项目采用） |
|---|---|---|
| 模型加载 | **每张重载 1~2.5 秒** | 常驻，只加载一次 |
| 输出目录不存在 | **静默失败，退出码仍为 0** | 不存在此问题 |
| 进度查询 | 只能解析 stderr | 有 `jobs/{id}` 接口 |
| 提示词 | 中文要写文件绕转义 | JSON 直传 |

最坑的一条是 **sd-cli 写文件失败时退出码依然是 0**，只在日志里留一行
`(failure)` / `0/1 images saved`。如果按退出码写驱动脚本，会安静地丢掉整批图。
所以本项目走 HTTP 服务，并配上**产物校验**（见 `目录结构说明.md` 的
「两个不能信的东西」）。

> 顺带记录：`-b N`（batch-count）对批量没用 —— 它只递增 seed，提示词是同一个。
> 批量要的是每张不同提示词，只能每张一次请求。
> 且 sd-cli 在 512×512 `-b 2` 曾报 `ErrorOutOfDeviceMemory`，而 `-b 4` 反而成功，
> 显存边界不稳，别贪。

## 2. 为什么 UI 必须是单文件

sd-server 的 `--serve-html-path` 把**一个** HTML 文件读进内存、只在根路径 `/`
返回，**不注册任何静态资源路由**（见 `<stable-diffusion.cpp>/examples/server/main.cpp`
的 `register_index_endpoints`）。所以：

- `<script src="script.js">` 外部脚本请求 `/script.js` 会 **404 白屏**
- UI 只能是「单个 HTML + 内联脚本」，不能拆成多文件/模块

这是**部署拓扑的硬约束**，不是维护风格问题。想真正拆分（比如自己起一个
能 serve 目录的静态服务、把 sd-server 当纯 API）属于换架构，是独立的大改动，
不该混在功能迭代里顺手做。

配套的协作规则见[单文件 UI 协作指南](单文件UI协作指南.md)。

## 3. 为什么前端无构建、无框架

- **零依赖、零打包**：双击 HTML 即用，改完刷新即生效，契合「本地工具」定位。
- 约 4900 行的前端逻辑全部内联，靠**一套 jsdom 测试**而不是构建工具来保证正确性。
  测试用 `window.eval` 读页面词法作用域里的 `const`（详见协作指南 §3），
  因此顶层变量**不能**改成 `var`、塞进闭包或 `type="module"`。
- 这套「单文件 + 测试兜底」是本项目的稳定形态；若要上框架/构建，
  等价于 §2 说的换架构，单独决策。

## 4. 批量组合：惰性 Fisher–Yates 保证「不重不漏」还能跑亿级空间

批量面板的「跳过重复」要在**巨大的组合空间**里连续抽出互不重复的组合。

- 组合空间是各占位符取值池的笛卡尔积（示例出厂配置数百、真实配置可达
  **亿级**）。如果预先生成全部组合再随机打乱，内存和时间都扛不住。
- 本项目用 **惰性 Fisher–Yates 部分洗牌**：维护一个稀疏的交换位 `Map`，
  每次只需 `O(镜头数)` 的工作量拿一张不重复组合，**不必物化整个空间**。
- 索引编解码（`decodeIdxs` / `keyToLinear`，混合进制）与 `templateHash`（djb2）
  在 UI 与终端脚本 `batch-run.mjs` 实现完全一致，保证两边算出的组合逐张对齐。

核心验证在 `tests/test-lazy-sampler.mjs`（抽满不重不漏、卡方均匀性、续跑重建、
稀疏内存、与旧全量枚举语义等价）。

## 5. 配置持久化为什么要第二个进程

sd-server **没有任何文件读写接口**，而浏览器的 File System Access API
**拿不到真实路径**（只能拿目录句柄）。所以「记住保存目录、跨刷新保留模板」必须靠
外部进程落盘 —— 这就是 `config-service/serve-config.mjs` 存在的意义。

它独立于生图，服务不可用时 UI 降级、主功能不受影响。只监听 `127.0.0.1` 并校验
`Origin`（非本机跨站拒绝）。接口清单与安全模型见[目录结构说明](目录结构说明.md)。

## 6. 终端批量与 UI 共享同一套逻辑

`tools/batch-run.mjs` **不重新实现**批量逻辑，而是复用 UI 那套：
占位符扫描 / 校验 / 渲染、标签摘要、索引编解码、惰性采样、带概率抽样。
因此「UI 里调好的模板，终端原样能跑」。

终端还能直接按模板库里的模板跑（`--template <id 或名字>`，`--list-templates` 看列表），
模板库是「一个模板一个文件」，CLI 只读不写。

实现细节（标签而非提示词、为什么必须走 `--job`、断点续跑快照、原子写）见
[目录结构说明](目录结构说明.md)。

> **两边同源的代价**：引擎函数在 UI 内联脚本与 `batch-run.mjs` 各有一份，
> 改一边必须同步另一边。已有的踩坑记录：抽样函数返回类型不统一
> （带概率返回下标数组、不带概率返回线性下标）导致「无概率模板 + 去重」崩溃，
> 详见[目录结构说明](目录结构说明.md)的 `--template` 段。

## 7. 怎么加接口 / 加功能 / 加测试

- **改 UI**：先读[单文件 UI 协作指南](单文件UI协作指南.md)（命名 / 作用域 / 测试链路）。
- **改配置服务接口**：改 `config-service/serve-config.mjs`，并同步
  `tests/test-open-dir.mjs` 与[目录结构说明](目录结构说明.md)的接口表。
- **加批量逻辑**：引擎纯函数分布在 UI 内联脚本与 `batch-run.mjs`，改一边要同步
  另一边；对应测试在 `tests/test-slot-engine.mjs` / `test-lazy-sampler.mjs` /
  `test-cli-*.mjs`。
- **改模板库**：服务端在 `serve-config.mjs`（`/templates` 路由 + `sanitizeTemplate`），
  UI 在 `tplLoad` / `tplPut` / `tplDelete`；对应测试 `tests/test-tpl-lib.mjs`
  （UI 侧）与 `tests/test-open-dir.mjs` K 段（服务端侧）。
- **跑测试**：见[目录结构说明](目录结构说明.md)或 README 测试区。

测试全部用临时配置 + 随机端口，**绝不碰用户真实的 `app\ui\config.json`**。
模板库同理：设了 `SDCFG_PATH` 时模板目录跟着配置走（`SDTPL_DIR` 可显式覆盖），
所以测试自动隔离，不会碰真实模板库。
