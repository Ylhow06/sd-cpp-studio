## 为什么这样分

### `app\runtime\` 单独一层

Windows 按**可执行文件所在目录**查找 dll，所以 `sd-server.exe` 和
`ggml-*.dll` / `stable-diffusion.dll` 必须同目录——**这一层内部不能再拆**。

但把它们从工程根挪进来是安全的：`serve.ps1` 用绝对路径定位 exe，
`--serve-html-path` 也用绝对路径，两者与 exe 的位置没有耦合。

### `config-service\` 独立

它和生图完全无关，只负责把配置写进 JSON：

- `sd-server` 没有任何文件读写接口，也没有静态目录功能
- 浏览器的 File System Access API **拿不到真实路径**（只能拿到目录句柄）
- 所以「记住保存目录」「跨刷新保留模板」必须靠外部进程落盘

设计上它是**可选的**：服务不可用时 UI 会降级（顶部状态条报错），
生图主功能不受影响。

### 路径全部自适应

`serve.ps1` 用 `$MyInvocation.MyCommand.Path` 推导工程根，
`serve-config.mjs` 用 `import.meta.url`，测试脚本同理。

**结果是整个目录可以随意改名 / 移动 / 换盘，不需要改任何代码。**

唯一写死的绝对路径是 `config.json` 里的 `saveDir`（图片保存目录），
那是用户数据，与工程位置无关。

## 运行时数据流

```
browser ──GET /sdcpp/v1/capabilities──► sd-server (1234)
        ──POST /sdcpp/v1/img_gen──────►
        ──GET  /sdcpp/v1/jobs/{id}────►

        ──GET/POST /config────────────► serve-config (1235) ──► app\ui\config.json
        ──POST /open-dir──────────────►                     ──► explorer.exe
        ──POST /run-cli───────────────►                     ──► output\.cli-jobs\job_*.json
                                                            ──► 终端: node tools\batch-run.mjs --job …
                                                                        └── HTTP ──► sd-server (1234)
```

两个服务**同生共死**：`serve.ps1` 启动时拉起两个，`Ctrl+C` 或关闭窗口时
用 `finally` 把配置服务一起停掉。

**但终端批量任务不受这个生命周期影响**：它一旦拉起就独立于浏览器运行，
浏览器关掉照常出图。它依赖的是 `sd-server` 本身（走 HTTP），
所以只要别把 `serve.cmd` 那个窗口也关了就行。

## 配置服务接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | 存活检查，返回配置路径 |
| GET | `/config` | 读配置（返回 `{ok, existed, bad, config}`） |
| POST | `/config` | 写配置（原子写：`.tmp` + fsync + rename） |
| POST | `/config/reset` | 恢复出厂 |
| POST | `/savedir` | 校验并登记保存目录 |
| POST | `/open-dir` | 在资源管理器打开目录 |
| GET | `/list-dir` | 列目录（目录选择用） |
| GET | `/drives` | 列盘符 |
| POST | `/run-cli` | **把一批交给终端跑**（落任务文件 + 拉起终端） |
| GET | `/run-cli/status` | 查最近一次终端任务 |
| GET | `/run-cli/state` | 读保存目录 `.batch-cli-state.json`，供 UI 探测「能否续跑」 |

**安全模型**：无白名单。只监听 `127.0.0.1`，并校验 `Origin`——
非本机的跨站请求一律拒绝，其余不限制路径。

### `/run-cli` 的安全边界

这个接口**会启动进程**，比「打开目录」危险得多，所以额外收紧：

- 可执行文件**写死** `process.execPath`（node 自身），脚本**写死**
  `<root>\tools\batch-run.mjs` —— 不接受任意命令
- 用户数据只作为**参数值**传入，且用 `spawn(..., { shell: false })` 传数组，
  **不存在命令拼接**
- 保存目录经 `checkOpenAllowed` 校验（不存在则建）
- 模板很长（中文），不走命令行 —— 先写进 `output\.cli-jobs\` 再交给脚本，
  避开 Windows 约 32K 的命令行上限
- 沿用 `originAllowed`：跨站请求一律 403
- 请求体里带 `dryRun: true` 时只落文件、回显 argv，**不真的起进程**（测试用）

## 终端批量脚本（`tools\batch-run.mjs`）

关掉浏览器也能跑的那条路。核心是**复用 UI 的同一套逻辑**，不是重新实现：

| 复用的函数 | 作用 |
|---|---|
| `scanSlots` / `validateTemplate` / `renderPrompt` | 占位符扫描、校验、渲染 |
| `labelOf` / `labelWidths` / `comboLabels` | 终端标签摘要（每值取前 5 字 + 对齐） |
| `decodeIdxs` / `templateHash` | 线性索引编解码、模板指纹 |
| 惰性 Fisher–Yates | 不重复抽样（与 UI 的 `LAZY_SAMPLER` 同一算法） |

所以 **UI 里调好的模板，终端原样能跑**。

### 终端打印标签而不是提示词

每张只列出各占位符**选中的值取前 5 个字**（`labelOf`），超长补 `…`，按槽对齐
（列宽取「该槽最长标签」和「槽名」的较大者，表头才不会顶开）。
一屏就能看出这批在覆盖哪片组合空间，不会被几百字提示词刷屏。

```text
        发型        · 氛围        · 饰品        · 场景        · 动作
  [待生成] 01. 20261007_235649_t2i_01_seed567084430.png
        黑色长发波… · 黄昏柔光，… · 只穿一双带… · 柔光下的双… · 正面直立站…
```

**只影响显示**：发给 sd-server 的 `prompt` 仍然是 `renderPrompt` 渲染出的完整提示词
（PNG 元数据里也是完整的），标签纯粹是终端可读性。

### 为什么必须走 `--job`

`config.json` 只存模板 / 数组 / 张数 / 保存目录 ——
**尺寸、步数、CFG、采样器、反向提示词只在浏览器内存里**（`S.m.txt2img`），
从来没落过盘。所以 UI 点按钮时必须把这份快照单独传过来，
否则终端会用脚本默认值出图，**比例和反向提示词全丢**。

`--job` 里的值可被命令行显式参数覆盖（`--w` / `--steps` 等），方便临时改。

### 两个不能信的东西

**1. 不能信退出码。** 这是从 `sd-cli.exe` 的教训来的 ——
它写文件失败时退出码**依然是 0**，只在日志里留 `(failure)`。
所以脚本对每张产出都做**产物校验**：检查文件存在、体积、PNG 文件头，
不通过就删掉并中止，绝不假装成功。

**2. 不能信「已提交」。** 生图是异步的：POST 只拿到 jobId，
必须轮询 `jobs/{id}` 直到 `completed`，再从 `result.images[0].b64_json`
取图。中途断线要重试，连续失败 20 次才判定失联。

### 断点续跑

进度写在**保存目录**的 `.batch-cli-state.json`（不在工程里，跟着图片走）。
采用「写 `.tmp` 再 `rename`」的原子替换，断电不会写坏。
状态文件是 **v2 快照**（`template` / `slots` / `neg` / `params` / `linears` / `done`），
所以续跑能完全复现旧批次，与当前编辑无关。

**默认总是开新批；只有明确加 `--resume`（或 UI 点「继续未完成批次」）
才续跑。**

- 已产出的图 → 跳过，不重复烧显卡
- 图在但进度丢了 → 校验后补记进度
- 续跑时 → **按旧快照**（模板/数组/参数/反向提示词/组合全用旧的那份），
  改提示词/参数后照样能续
- 旧版 v1 进度（没存 `slots`）→ 不算可续，只能开新批

> **这段逻辑是逐步收敛的**：最初「检测到未完成批次就自动续」，结果是
> 用户点两次按钮以为在跑新一批，却得到 `0 张新图 / 跳过 2 张`。后改成「显式选择
> 继续/开新」+「续跑按旧快照」。续不续都先给一句话（`检测到未完成批次 X（1/3）…`），
> 绝不闷头开新批。
> CLI 行为矩阵见 `tests/test-cli-resume.mjs`（A–G），UI 的按钮/状态
> 见 `tests/test-cli-mode-ui.mjs`。

## 两个容易踩的点

### 1. 主图自适应不要退回百分比高度

`#stage` 的高度由 flex 分配（**没有确定值**），所以里面的元素写
`max-height:100%` 是**解析不到的**，竖图会按原始高度撑开、被 `overflow:hidden` 切掉。

正确做法是让图片脱离内容流：

```css
#stage  { position:relative; padding:12px 20px; overflow:hidden }
#imgWrap{ position:absolute; inset:12px 20px }
#imgWrap img{ position:absolute; inset:0; width:100%; height:100%;
              object-fit:contain; object-position:center }
```

`inset` 给出**确定的尺寸**，百分比必然可解析。
`test-lightbox.mjs` 里有专门盯这条的回归断言。

### 2. 蒙版画布要跟着图片的实际渲染框走

图片用 `object-fit:contain` 居中后，四周会有留白。
蒙版若用 `inset:0` 硬铺满容器，**画笔坐标就会错位**（点在图上，涂到留白区）。

`syncMaskLayerToImage()` 按图片的真实渲染矩形同步蒙版的位置与尺寸，
在刷新主图 / 图片加载完成 / 窗口 resize 时都会重新对齐。
