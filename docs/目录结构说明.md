## 为什么这样分

### `app\runtime\` 单独一层

Windows 按**可执行文件所在目录**查找 dll，所以 `sd-server.exe` 和
`ggml-*.dll` / `stable-diffusion.dll` 必须同目录——**这一层内部不能再拆**。

但把它们从工程根挪进来是安全的：`serve.ps1` 用绝对路径定位 exe，
`--serve-html-path` 也用绝对路径，两者与 exe 的位置没有耦合。

### `config-service\` 独立

它和生图完全无关，只负责把配置写进 JSON：

- `sd-server` 没有任何文件读写接口，也没有静态目录功能
- 浏览器的 File System Access API **拿不到真实路径**（只能拿到目录句柄）
- 所以「记住保存目录」「跨刷新保留模板」必须靠外部进程落盘

设计上它是**可选的**：服务不可用时 UI 会降级（顶部状态条报错），
生图主功能不受影响。

### 路径全部自适应

`serve.ps1` 用 `$MyInvocation.MyCommand.Path` 推导工程根，
`serve-config.mjs` 用 `import.meta.url`，测试脚本同理。

**结果是整个目录可以随意改名 / 移动 / 换盘，不需要改任何代码。**

唯一写死的绝对路径是 `config.json` 里的 `saveDir`（图片保存目录），
那是用户数据，与工程位置无关。

## 运行时数据流

```
browser ──GET /sdcpp/v1/capabilities──► sd-server (1234)
        ──POST /sdcpp/v1/img_gen──────►
        ──GET  /sdcpp/v1/jobs/{id}────►

        ──GET/POST /config────────────► serve-config (1235) ──► app\ui\config.json
        ──GET/PUT/DELETE /templates───►                     ──► app\ui\templates\<id>.json
        ──POST /open-dir──────────────►                     ──► explorer.exe
        ──POST /run-cli───────────────►                     ──► output\.cli-jobs\job_*.json
                                                            ──► 终端: node tools\batch-run.mjs --job …
                                                                        └── HTTP ──► sd-server (1234)
```

两个服务**同生共死**：`serve.ps1` 启动时拉起两个，`Ctrl+C` 或关闭窗口时
用 `finally` 把配置服务一起停掉。

**但终端批量任务不受这个生命周期影响**：它一旦拉起就独立于浏览器运行，
浏览器关掉照常出图。它依赖的是 `sd-server` 本身（走 HTTP），
所以只要别把 `serve.cmd` 那个窗口也关了就行。

## 配置服务接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | 存活检查，返回配置路径 |
| GET | `/config` | 读配置（返回 `{ok, existed, bad, config}`） |
| POST | `/config` | 写配置（原子写：`.tmp` + fsync + rename） |
| POST | `/config/reset` | 恢复出厂（`FACTORY`，即那份**教学示例**） |
| GET | `/templates` | 列出模板库（读 `<模板目录>/*.json`，按时间倒序） |
| GET | `/templates/<id>` | 读单个模板 |
| PUT | `/templates/<id>` | 新建/覆盖单个模板（原子写） |
| DELETE | `/templates/<id>` | 删除单个模板（幂等） |
| POST | `/savedir` | 校验并登记保存目录 |
| POST | `/open-dir` | 在资源管理器打开目录 |
| GET | `/list-dir` | 列目录（目录选择用） |
| GET | `/drives` | 列盘符 |
| POST | `/run-cli` | **把一批交给终端跑**（落任务文件 + 拉起终端） |
| GET | `/run-cli/status` | 查最近一次终端任务 |
| GET | `/run-cli/state` | 读保存目录 `.batch-cli-state.json`，供 UI 探测「能否续跑」 |

**安全模型**：无白名单。只监听 `127.0.0.1`，并校验 `Origin`——
非本机的跨站请求一律拒绝，其余不限制路径。

### 模板库：一个模板一个文件

用户模板库存在 `<root>\app\ui\templates\<id>.json`，**不在 `config.json` 里**。

为什么拆开：`config.json` 是**整份覆盖**写的（页面内存里持有一份副本，
任何编辑触发防抖保存就把整份写回）。模板挤在这个数组里时，手工改过的内容
会被一次普通保存静默抹掉。拆成独立文件后，一个模板一个文件，
**直接打开就能改、改完即生效**，且不会被配置保存波及。

- 文件名用 `id`（`tpl_xxx`），稳定、无中文/空格转义问题；改名不动文件
- `id` 只允许 `[A-Za-z0-9_-]`，服务端严格校验（它是文件名的一部分，
  是路径注入的入口），并二次确认解析后的路径仍在模板目录内
- 数量不设上限
- 首次启动会把旧 `config.json` 里的 `templates` 自动迁移成独立文件，
  然后移除该字段；**已存在的同名文件不覆盖**（独立文件是权威源）
- `templates/` 与 `config.json` 一样不入版本控制（个人数据）
- UI 的「📂 模板文件夹」按钮走 `/open-dir` 直接打开这个目录

### 占位符出现概率与条件块

槽位可选字段 `p`：该占位符在每张图里**出现**的概率。

| `p` | 含义 |
|---|---|
| 缺省 / `p >= 1` / 非数字 | **必选**（100%，字段不落盘） |
| `0 < p < 1` | 可选，按该概率出现 |

```jsonc
{ "name": "眼镜", "values": ["银色细框圆形眼镜", "金色细框圆形眼镜"], "p": 0.2 }
```

模板里用**条件块**包住「标签 + 占位符」，缺席时整块删除：

```
{{#眼镜}}眼镜：{{眼镜}}；{{/眼镜}}鞋子（必穿）：{{鞋子}}。
```

- 只把 `{{眼镜}}` 换成空串会留下 `眼镜：；` 这种空标签污染提示词，
  所以标签必须一起包进块里
- 缺席**不能用空字符串表示**：`slotValues` 会 `filter(v => v !== '')`
  把空串静默吞掉，导致概率失效。缺席走**独立下标通道**（`idxs = -1`）
- `p` 允许范围 `(0, 1]`，**禁止 0**（永不出现是死配置，没有意义）
- 服务端 `sanitize` 是白名单重建，**两处**（`batch.slots` 与模板 slots）
  都要透传 `p`，否则概率会在每次保存时被静默丢弃

### 去重（「跳过重复组合」）何时被禁用

```
可用 ⟺ 模板实际引用的槽位里没有 0<p<1 的槽位
       且 组合总数 ∏N ≤ 2^53-1（Number.isSafeInteger）
```

- 有概率槽位 → 去重会扭曲概率分布，且「要概率就意味着接受重复」
- 组合空间超出精确整数范围 → 混合进制索引失真，抽样不再可靠
- 禁用只是**运行时忽略**：字段原样保留，删掉概率后去重自动回来
- 禁用时开关**置灰**、旁注原因、上方文案改「允许重复」，不报红也不拦截
- 判定范围**只算模板实际引用的槽位**（定义了但没用的槽位不影响输出）
- `p = 1` 与不写 `p` 等价，**不禁用**去重

### 模板写法速查（`#tplHelp`）

条件块语法**此前在 UI 上没有任何入口** —— 只写在源码注释和文档里，
等于「功能存在但没人知道」。批量面板上新增了速查区：

| 项 | 实现 |
|---|---|
| 元素 | `<details id="tplHelp">`，**默认收起**（不占面板高度）|
| 折叠 | 用原生 `details`/`summary`，**不需要 JS** |
| 内容 | `{{名称}}` 与 `{{#名称}}…{{/名称}}` 的写法、命名规则、可直接抄的最小示例、可选占位符示例 |

内容里给的示例**必须真的能跑** —— 教程教错了比没有教程更糟。
`tests/test-slot-dlg.mjs` 第 11 节会把速查里的示例拿去 `validateTemplate`
和 `renderPrompt` 实跑一遍，断言「零错误、零警告、缺席时不留空标签」。

### 警告通道（`#tplWarn`，黄色）

与红色报错**分开**：报错拦生成，警告只提醒。

目前只有一种警告：**可选占位符（`0<p<1`）没有被条件块包住**。

```
眼镜：{{眼镜}}。      →  💡 「眼镜」设了出现概率，但模板里有一处
                         没有用 {{#眼镜}}…{{/眼镜}} 包住…
```

| 决策 | 理由 |
|---|---|
| 做成**警告**而非错误 | 它不是语法错误，模板完全能跑；硬拦会挡住本来可用的模板，比不拦更糟 |
| 有错误时**不再叠警告** | 避免红黄一起刷屏，先把错误解决了再看警告 |
| 同一占位符多处裸写**只报一条** | 同一件事不刷屏 |
| 判定按**出现位置**而非占位符 | 同一占位符「一处包了块、一处裸写」仍然要报 —— 那处裸写确实会出问题 |

实现见 `warnTemplate()`（与 `validateTemplate()` 并列，**不进 errors 数组**）。

### 占位符标签行（`#tplTags`）：三态 + 点击行为

模板输入框下面那行标签是**全部占位符的并集**（不是只有用到的），分三态：

| 状态 | 条件 | 外观 | 点击 |
|---|---|---|---|
| **亮** | 已使用 + 有取值 | 实线边框、正常字色 | 追加 `{{名称}}` 到模板末尾 |
| **暗** | 未使用（不管有无取值） | 虚线边框、降级字色 | 追加 `{{名称}}` 到模板末尾 |
| **红** | 已使用 + 没取值 | 红边框、红字 | 打开取值编辑器去新增/编辑 |

**为什么是并集**：只列「用到的」就看不到「配了但没用」的数组 ——
用户既发现不了它，也没法把它插进模板；只列「配了的」就看不到
模板里引用了但还没建数组的名字（那是要报错的）。

**排序**：先按模板里的出现顺序，再补上剩余的未使用项（按数组顺序）。
这样标签行的顺序与模板读起来一致，未使用的排在后面不干扰视线。

**「未使用 + 空数组」为什么是暗而不是红**：那只是个还没写完的草稿。
标红会让「刚点＋新增」的槽位看起来像出错了。一旦点它追加进模板
（变成已使用），仍为空就会自动转红 —— 路径自洽，不会卡在中间态。
角标文案也跟着分：红的说「缺数组」（错误状态），暗的说「0 条」（草稿）。

**追加是允许重复的**：同名占位符在一张图里取同一个值，所以重复出现
不会自相矛盾，组合数也不受影响（按去重后的名字算）。
重复点击就重复追加（等于提高该维度在提示词里的权重）。

**红色标签的跳转是一步到位的**：名字不存在时**自动新建同名空槽**再定位，
省掉「新建 → 手打名字」两步；已存在（含空数组）则直接定位过去，不重复新建。

**修掉的一个隐性失效**：重构前标签点击是「滚动到 `#slotList` 里对应槽位并聚焦」。
占位符编辑器改成弹窗后，`#slotList` 变成 `hidden` 的「真相容器」，
对隐藏元素做 `scrollIntoView` / `focus` **都不生效** —— 表现为「点了没反应」。
新实现完全不依赖那个容器。

实现：`tplTagItems()` 算状态、`renderTplTags()` 渲染、`appendSlotToTpl()`
追加、`editSlotByName()` 跳转编辑。测试见 `tests/test-slot-dlg.mjs` 第 13–16 节。

### `/run-cli` 的安全边界

这个接口**会启动进程**，比「打开目录」危险得多，所以额外收紧：

- 可执行文件**写死** `process.execPath`（node 自身），脚本**写死**
  `<root>\tools\batch-run.mjs` —— 不接受任意命令
- 用户数据只作为**参数值**传入，且用 `spawn(..., { shell: false })` 传数组，
  **不存在命令拼接**
- 保存目录经 `checkOpenAllowed` 校验（不存在则建）
- 模板很长（中文），不走命令行 —— 先写进 `output\.cli-jobs\` 再交给脚本，
  避开 Windows 约 32K 的命令行上限
- 沿用 `originAllowed`：跨站请求一律 403
- 请求体里带 `dryRun: true` 时只落文件、回显 argv，**不真的起进程**（测试用）

## 终端批量脚本（`tools\batch-run.mjs`）

关掉浏览器也能跑的那条路。核心是**复用 UI 的同一套逻辑**，不是重新实现：

| 复用的函数 | 作用 |
|---|---|
| `scanSlots` / `validateTemplate` / `renderPrompt` | 占位符扫描、校验、渲染 |
| `labelOf` / `labelWidths` / `comboLabels` | 终端标签摘要（每值取前 5 字 + 对齐） |
| `decodeIdxs` / `templateHash` | 线性索引编解码、模板指纹 |
| 惰性 Fisher–Yates / `drawProbCombos` | 不重复抽样 / 带概率抽样（与 UI 同一算法） |

所以 **UI 里调好的模板，终端原样能跑**。

### 按模板库里的模板跑（`--template`）

模板库是「一个模板一个文件」，CLI 可以直接按 id 或名字取用：

```bat
node tools\batch-run.mjs --list-templates          :: 列出模板库后退出
node tools\batch-run.mjs --template 裙子女生·竖版    :: 按名字（支持唯一前缀）
node tools\batch-run.mjs --template tpl_xxx         :: 按 id
node tools\batch-run.mjs --template tpl_xxx --tpl-dir D:\my-tpl   :: 指定模板目录
```

- 模板自带的 `count` / `skipDup` 生效；命令行显式参数（`--count` 等）优先
- 名字支持**唯一前缀匹配**；不唯一时列出候选并报错，**绝不静默换一个模板**
- 与 `--job` **互斥**（两者都在指定模板来源）
- 模板目录默认与 `config.json` 同级（`app\ui\templates\`），可用 `--tpl-dir` 覆盖
- `--list-templates` 不需要保存目录、也不需要生图服务

> **两条抽样路径必须统一成「各槽下标」**：带概率的模板走 `drawProbCombos`
> （直接返回下标数组），不带概率的走 `drawCombos`（返回**线性下标**数字）。
> 后者必须先经 `decodeIdxs` 展开再存进 `idxRows`，否则读取时按数组用会抛
> `idxs.map is not a function` —— 这是「无概率模板 + 去重」的必现崩溃，
> 回归见 `tests/test-cli-template.mjs` G 段。

### 终端打印标签而不是提示词

每张只列出各占位符**选中的值取前 5 个字**（`labelOf`），超长补 `…`，按槽对齐
（列宽取「该槽最长标签」和「槽名」的较大者，表头才不会顶开）。
一屏就能看出这批在覆盖哪片组合空间，不会被几百字提示词刷屏。

```text
        发型        · 氛围        · 饰品        · 场景        · 动作
  [待生成] 01. 20261007_235649_t2i_01_seed567084430.png
        黑色长发波… · 黄昏柔光，… · 只穿一双带… · 柔光下的双… · 正面直立站…
```

**只影响显示**：发给 sd-server 的 `prompt` 仍然是 `renderPrompt` 渲染出的完整提示词
（PNG 元数据里也是完整的），标签纯粹是终端可读性。

### 为什么必须走 `--job`

`config.json` 只存批量面板的当前状态（模板 / 数组 / 张数 / 保存目录）——
**尺寸、步数、CFG、采样器、反向提示词只在浏览器内存里**（`S.m.txt2img`），
从来没落过盘。所以 UI 点按钮时必须把这份快照单独传过来，
否则终端会用脚本默认值出图，**比例和反向提示词全丢**。

`--job` 里的值可被命令行显式参数覆盖（`--w` / `--steps` 等），方便临时改。

### 两个不能信的东西

**1. 不能信退出码。** 这是从 `sd-cli.exe` 的教训来的 ——
它写文件失败时退出码**依然是 0**，只在日志里留 `(failure)`。
所以脚本对每张产出都做**产物校验**：检查文件存在、体积、PNG 文件头，
不通过就删掉并中止，绝不假装成功。

**2. 不能信「已提交」。** 生图是异步的：POST 只拿到 jobId，
必须轮询 `jobs/{id}` 直到 `completed`，再从 `result.images[0].b64_json`
取图。中途断线要重试，连续失败 20 次才判定失联。

### 断点续跑

进度写在**保存目录**的 `.batch-cli-state.json`（不在工程里，跟着图片走）。
采用「写 `.tmp` 再 `rename`」的原子替换，断电不会写坏。
状态文件是 **v2 快照**（`template` / `slots` / `neg` / `params` / `idxRows` / `done`），
所以续跑能完全复现旧批次，与当前编辑无关。

> `idxRows` 是**每张的各槽下标**（缺席记 `-1`）。更早的快照存的是 `linears`
> （线性下标），读取时仍兼容 —— 没有 `idxRows` 就按 `linears` 解码。

**默认总是开新批；只有明确加 `--resume`（或 UI 点「继续未完成批次」）
才续跑。**

- 已产出的图 → 跳过，不重复烧显卡
- 图在但进度丢了 → 校验后补记进度
- 续跑时 → **按旧快照**（模板/数组/参数/反向提示词/组合全用旧的那份），
  改提示词/参数后照样能续
- 旧版 v1 进度（没存 `slots`）→ 不算可续，只能开新批

> **这段逻辑是逐步收敛的**：最初「检测到未完成批次就自动续」，结果是
> 用户点两次按钮以为在跑新一批，却得到 `0 张新图 / 跳过 2 张`。后改成「显式选择
> 继续/开新」+「续跑按旧快照」。续不续都先给一句话（`检测到未完成批次 X（1/3）…`），
> 绝不闷头开新批。
> CLI 行为矩阵见 `tests/test-cli-resume.mjs`（A–G），UI 的按钮/状态
> 见 `tests/test-cli-mode-ui.mjs`。

## 占位符取值编辑器（弹窗：左选 / 右编辑）

「随机取值数组」的编辑器是**独立弹窗**（`#slotDlg`），不是平铺在批量面板里 ——
裙子模板有 11 个占位符，平铺会把面板撑得极长，改一个要来回滚。

- 面板上只留**摘要标签**（名字 · 条数 · 概率角标）+「✏️ 编辑占位符取值」按钮；
  空数组或未被模板引用的会标红，点标签直接跳到该项
- 弹窗左栏选占位符、右栏编辑当前这一个（名称 / 概率 / 取值 / 删除）
- 尺寸 `1040×760`，上限 `94vw / 88vh`；Escape / 点遮罩 / 「完成」都能关

**关键实现约束**：编辑器渲染在弹窗里，但 `#slotList` 仍保留在 DOM 中（`hidden`），
弹窗的 textarea 与它**双向同步**。

为什么不能直接把节点搬进弹窗：`saveBatchPane()` 是遍历 `#slotList .slot`
读 `[data-slotvals]` 的，节点搬走会让它读不到 → **用户编辑被静默丢弃**。
所以隐藏的那份始终是「真相容器」，弹窗只是同一批控件的另一种摆放。

### 行号槽必须按「视觉行」编号

长取值会在 textarea 里**软换行**成多个视觉行。若按逻辑行（换行符）编号，
第 2 个编号会落到第 1 条取值的续行上 —— 完全错位。

正确做法：**首行给编号，续行给空占位**（`gutterItemsFor`），
用一个隐藏镜像元素（`#nvMirror`）按相同宽度与字体测量每条占几行
（`measureVisualRows`）。两个坑：

- 镜像的排版属性要**逐项从 textarea 的 computedStyle 抄**（宽度、字体、
  行高、`white-space`/`overflow-wrap`/`word-break`），不能硬编码 ——
  换行规则由浏览器给 textarea 的默认值决定
- `computedStyle.lineHeight` **可能是无单位值**（`"1.7"` 而不是 `"21.25px"`），
  直接 `parseFloat` 当像素用会算出垃圾行数。必须经 `resolveLineHeightPx()` 换算

拿不到布局时（隐藏容器 / jsdom）退化为「一逻辑行一个编号」，不崩。
回归见 `tests/test-slot-dlg.mjs` 第 10 段。

## 两个容易踩的点

### 1. 主图自适应不要退回百分比高度

`#stage` 的高度由 flex 分配（**没有确定值**），所以里面的元素写
`max-height:100%` 是**解析不到的**，竖图会按原始高度撑开、被 `overflow:hidden` 切掉。

正确做法是让图片脱离内容流：

```css
#stage  { position:relative; padding:12px 20px; overflow:hidden }
#imgWrap{ position:absolute; inset:12px 20px }
#imgWrap img{ position:absolute; inset:0; width:100%; height:100%;
              object-fit:contain; object-position:center }
```

`inset` 给出**确定的尺寸**，百分比必然可解析。
`test-lightbox.mjs` 里有专门盯这条的回归断言。

### 2. 蒙版画布要跟着图片的实际渲染框走

图片用 `object-fit:contain` 居中后，四周会有留白。
蒙版若用 `inset:0` 硬铺满容器，**画笔坐标就会错位**（点在图上，涂到留白区）。

`syncMaskLayerToImage()` 按图片的真实渲染矩形同步蒙版的位置与尺寸，
在刷新主图 / 图片加载完成 / 窗口 resize 时都会重新对齐。
