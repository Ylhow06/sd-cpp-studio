## 一、最终决策清单

### 1. 批量语义

| 项 | 决策 |
|---|---|
| 随机方式 | **A · 每张独立随机取值**（允许重复） |
| 批量张数 | **输入框**（替代现有 `min=1 max=8` 滑块） |
| 占位符数量 | 用户自定义 |
| 每个数组长度 | 用户自定义 |
| 跳过重复组合 | **提供开关**；启用时 `张数 ≤ 组合数` |

### 2. 占位符

| 项 | 决策 |
|---|---|
| 语法 | `{{名称}}` 双花括号 |
| 名称规则 | 允许中文，**禁止空格**，不含 `{` `}` |
| 同名占位符 | **同一次生成内取值一致**（必须，否则画面自相矛盾） |
| 未匹配数组 | 报错并**硬拦** |
| 空数组 | 等同未匹配，**一起拦** |
| 未闭合 `{{` | **报红** |
| 报错强度 | **实时标红（丙） + 点生成时硬拦（甲）** |

#### 3.1 现状：出厂示例

出厂内容从「一套长身份描述模板」改成了**短小的教学示例**：

```
一位20岁中国女孩的全身生活照，从头到脚完整入镜，人物占画面主体。
服装：{{服装}}。场景：{{场景}}。姿势：{{动作}}。
真实抓拍风格，纪实生活摄影，自然光，手机拍摄质感，写实。
```

| 项 | 值 |
|---|---|
| 占位符 | 3 个（服装 6 / 场景 6 / 动作 8 = **288 组合**）|
| 概率 | 全部必选（无 `p` 字段）|
| 按钮 | 「**恢复示例**」（原「恢复默认模板」）|
| 确认框 | 说明「教学示例，不是推荐配置」+「已存模板不受影响」|

**为什么改**：原来的长模板对**已经会用的人**是好用的，但对第一次打开的人
是一堵墙 —— 三段长文本 + 一个身份描述，看不出「哪些字是我该改的」。
示例的职责是**教语法**，不是提供最佳出图参数；真要长期用的模板应该存进
「我的模板」里（示例也已在确认框里这么引导）。

**改名的理由**：叫「恢复默认」会让人以为「点了能回到推荐配置」，
点完发现拿到一份很短的演示内容，是**期望落差**。叫「恢复示例」就把
它的定位说清楚了。

**配套**：面板上新增「模板写法速查」（`#tplHelp`，`<details>` 默认收起），
补齐此前**在 UI 上完全没有入口**的条件块语法。详见
[目录结构说明 · 模板写法速查](目录结构说明.md#模板写法速查tplhelp)。

#### 3.2 构图原则（实测经验，换示例时不要丢）

这段经验是从「出厂模板该长什么样」的实测里总结出来的，
**现在不再由出厂示例承载，但配置自己的模板时依然成立**：

身份块很长，会把模型权重压在脸上，默认出图会变成「胸部以上半身」，
导致服装和腰部以下的姿势全部体现不出来。

解决办法是【**构图前置 + 末尾重复**】：

1. 把「全身构图」写在模板**最开头**（开头权重最高）
2. 结尾再用一句「全身站姿，完整展示服装」加固
3. 身份块保持完整（脸的一致性靠它），但不再让它独占权重

实测失败例（半身时代）：举起奶茶（杯子裁在画面边缘）、低头挑选水果
（水果在底部被裁）、撑伞回头（伞面出画）、靠着栏杆（栏杆不在画面内）。

姿势数组一律用【**静态站姿**】——动态动作（走、蹲、跑）在这套写实风格下
容易崩肢体，静态站姿稳定且能展示整套服装。

> 这条经验**只对「有人物身份一致性要求」的模板成立**。示例模板短、
> 没有身份块，所以不需要这套处理 —— 这也是它不适合当推荐配置的原因。

**chips**：批量 tab **不放** chips，与现有 `PRESETS` 完全解耦。

### 4. 生成参数

| 项 | 决策 |
|---|---|
| 参数来源 | **路线乙 · 继承文生图**（尺寸/步数/CFG/种子/采样器/调度器/反向提示词） |
| 批量 tab 自有控件 | 仅 **模板文本 + 占位符数组编辑器 + 张数 + 跳过重复开关** |
| 参数一致性 | **启动时冻结快照**；改文生图参数不影响进行中的批次 |

### 5. 断点续跑（1 档）

| 项 | 决策 |
|---|---|
| 恢复范围 | **只续计划，不恢复图片**；缩略图条刷新后清空 |
| 已算完的那张 | **直接跳过**（不重挂载 jobId） |
| 跑完 | 保留记录，显示「已完成 N 张」+「开始新批次」按钮 |
| 未完成 + 刷新 | **提示"检测到未完成的批次（7/20），继续吗？"，不自动跑** |
| 改模板后 | **旧计划作废**，提示"模板已修改，之前的进度已重置" |
| 点取消 | **保留计划**（取消 = 暂停）；另设「放弃本批次」按钮 |
| 服务器重启 | 续跑时**直接重新提交**，最多多烧一张的时间 |

### 6. 持久化

| 项 | 决策 |
|---|---|
| 方案 | **A · Node 辅助服务落磁盘**（sd-server 无任何读写接口，无静态目录服务） |
| 运行时 | Node（已装 v24.19.0） |
| 监听 | `127.0.0.1:1235` |
| 配置文件 | `app/ui/config.json`（批量面板当前状态：模板/数组/张数/保存目录） |
| 模板库 | **一个模板一个文件**：`sd-cpp/ui/templates/<id>.json`（后续加入，不再挤在 config.json） |
| 服务脚本 | `sd-cpp/config-service/serve-config.mjs` |
| 启动方式 | **甲**：`serve.ps1` 同时起 sd-server + Node，关窗口一起收 |
| Node 挂掉 | **甲**：页面照常工作，批量 tab 顶部提示"配置服务未启动"，配置不保存，**不阻断主功能** |
| 写入时机 | **丙**：改动立刻写（**防抖 500ms**）+ 顶部显示"已保存"状态 |

**模板库为什么拆成独立文件**：`config.json` 是**整份覆盖**写的（页面内存里
持有一份副本，任何编辑触发防抖保存就整份写回）。模板挤在这个数组里时，
手工改过的内容会被一次普通保存静默抹掉。拆开后一个模板一个文件，
**直接打开就能改、改完即生效**。文件名用 `id`（稳定、无中文/空格转义问题，
改名不动文件），`id` 严格限制 `[A-Za-z0-9_-]` 并二次校验路径未越界。
首次启动会把旧 `config.json` 里的 `templates` 自动迁移出来。

**独立第 4 个 tab**，`data-mode="batch"`，加入 `S.m` 状态机。

### 8. 终端运行（关掉浏览器也能跑）

| 项 | 决策 |
|---|---|
| 动机 | 浏览器在整条链路里几乎不耗 CPU（单张约 40 秒时 GPU 是 100%），但**关掉浏览器批次就停** —— 这是「连续性」问题，不是「性能」问题 |
| 传输方式 | **HTTP**（`sd-server` 的 `/sdcpp/v1/img_gen`），不用 `sd-cli.exe` |
| 驱动 | `tools\batch-run.mjs`（Node，复用 UI 的同一套组合逻辑） |
| 唤起 | UI 按钮 → `POST /run-cli` → 落任务文件 → `cmd /k node … --job` 起可见终端 |
| 参数传递 | **完整快照**（见下），不能只让脚本读 `config.json` |
| 进度 | 保存目录下的 `.batch-cli-state.json`，原子写；**默认开新批，加 `--resume` ／UI 点「继续」才续跑** |
| 产物校验 | **不信任退出码**，逐张校验 PNG 文件头 + 体积 |
| 终端输出 | 每张打印**各占位符选中的值取前 5 个字**（不是整段提示词） |
| 继续/新批 | UI 探测 `/run-cli/state`，按钮在「继续未完成批次」与「开新批」之间自动切换，状态条明示 |

**为什么终端打标签而不是提示词**：真实模板的提示词是几百字长句（含换行），
打出来会刷屏且看不出批次在覆盖哪片组合空间。改成「每个占位符取前 5 个字」后，
一屏能对比多张的组合差异。**出图不受影响** —— 发给 `sd-server` 的 `prompt`
仍是 `renderPrompt` 渲染的完整提示词，PNG 元数据里也是完整的。

实现只有一条规则（`labelOf`）：折叠空白 → 取前 `LABEL_CHARS`（5）个字 → 超长补 `…`。
列宽取「该槽最长标签」与「槽名」的较大者，保证表头与标签列对齐。
按码点切分（`[...str]`），不会切碎 emoji 代理对。

> 设计取舍：曾试过「按终端显示宽度截断 + 重名时跳过共同前缀 / 头尾截断 / 自动加宽」，
> 逻辑复杂且产出不稳定（`室…暖` 这类无信息标签）。统一取前 5 字更简单、可预期。

**续跑/开新批的决策**（不是自动续）：

| 场景 | UI | 脚本行为 |
|---|---|---|
| 无未完成批次 | 单按钮「在终端运行这一批」 | 开新批 |
| 有可续的未完成批次（v2 快照） | 主按钮「**继续未完成批次（2/5）**」+ 旁边「开新批次」 | `--resume` 续 | 开新批 |
| 有未完成批次但不想续 | 点「开新批次」 | 开新批（旧者作废） |
| 旧批次已完成 | 单按钮，状态条「上次已完成」 | 开新批 |
| 旧版进度（v1 无快照） | 单按钮，状态条「无法续」 | 开新批 |

**续跑按旧快照进行，与当前编辑无关**：`--resume`（或 UI 点「继续」）时，
模板、数组、参数（尺寸/步数/CFG/采样器）、反向提示词、组合 `linears`、
种子全部取自状态文件里存的 v2 快照，把剩下没出完的按原样出完 ——
所以**改提示词、改参数之后照样能找到旧批次续跑**。

实现：UI 调新增 `GET /run-cli/state?dir=…` 读到 `.batch-cli-state.json` 的
`{done,count,finished,resumable,hasSnapshot,templateHash}`，不再和当前模板比对；
按钮 `#cliRun.dataset.mode` 决定 `POST /run-cli` 的 `mode:"new|resume"`，
有可续批次时额外显示 `#cliRunNew`（永远 `new`）。脚本侧 `applyJob` 把
`mode:"resume"` 映射到 `o.resume`；`main()` 里若 `o.resume` 且有 v2 快照，
则从快照重建整个批次，跳过「取当前 config / --job」那一步。

状态文件为 v2：新增 `template / slots / neg`，连同原有的 `params / linears /
done / seedBase`，使续跑完全自洽。旧版 v1 状态（无 `slots`）不在「可续」之列。

> **为什么要显式，不自动续**：最初实现是「检测到未完成批次就自动续」。结果
> 用户点两次按钮自认在跑新一批，却得到 `0 张新图 / 跳过 2 张` —— 完全不知道
> 自己跑的是继续还是新批。改成上面这套：续不续都先说清楚，绝不闷头开新批。
> CLI 行为矩阵见 `tests/test-cli-resume.mjs`（A–G），UI 见 `tests/test-cli-mode-ui.mjs`。

**为什么必须是「完整快照」**：`config.json` 只存模板 / 数组 / 张数 / 保存目录，
尺寸 / 步数 / CFG / 采样器 / 反向提示词**只在浏览器内存里**（`S.m.txt2img`）。
只让脚本读配置文件的话，终端会用默认值出图，**比例和反向提示词全丢**。

**为什么不用 `sd-cli.exe`**（实测结论）：

| | `sd-cli.exe` | `sd-server` + HTTP |
|---|---|---|
| 模型加载 | 每张重载 1~2.5s（`--offload-to-cpu` 下实测） | 常驻，只加载一次 |
| 输出目录不存在 | **静默失败，退出码仍为 0** | 不存在此问题 |
| 进度查询 | 只能解析 stderr | `jobs/{id}` 接口 |
| 提示词 | 中文需写文件绕转义 | JSON 直传 |

实测补充：`-b N` 对批量生图无用（只递增 seed，提示词相同）；
512×512 时 `-b 2` 曾报 `ErrorOutOfDeviceMemory` 而 `-b 4` 成功，显存边界不稳。

**`/run-cli` 的安全边界**：可执行文件写死为 `process.execPath`、脚本写死为
`tools\batch-run.mjs`，用户数据仅作参数值且 `spawn(..., {shell:false})` 传数组
（无命令拼接）；保存目录经校验；模板先落文件再传路径，避开命令行长度上限；
沿用 `originAllowed` 反跨站。

## 二、数据模型

`app/ui/config.json`（**不含 `templates`** —— 模板库已拆成独立文件）：

```json
{
  "version": 1,
  "batch": {
    "template": "一位20岁中国女孩……{{#眼镜}}眼镜：{{眼镜}}；{{/眼镜}}鞋子（必穿）：{{鞋子}}。……",
    "slots": [
      { "name": "服装", "values": ["黑色皮夹克内搭白T恤", "黄色针织马甲配牛仔短裙"] },
      { "name": "场景", "values": ["夜晚拥挤的夜市街道", "日落时分的海边沙滩"] },
      { "name": "眼镜", "values": ["银色细框圆形眼镜", "金色细框圆形眼镜"], "p": 0.2 }
    ],
    "skipDup": true,
    "count": 20
  },
  "plan": {
    "id": "batch-20261006-091500",
    "v": 2,
    "status": "idle",
    "total": 20,
    "cursor": 0,
    "slotNames": ["服装", "场景", "眼镜"],
    "combos": [[0, 0, -1], [1, 1, 0]],
    "usedCombos": [],
    "templateHash": "a1b2c3d4",
    "frozen": {
      "width": 768, "height": 768, "steps": 8, "cfg": 1.0,
      "sampler": "euler", "scheduler": "discrete",
      "seed": -1, "negative": ""
    },
    "results": []
  }
}
```

模板库文件 `app/ui/templates/<id>.json`（一个模板一个文件）：

```json
{
  "id": "tpl_muwcqto6_skirt_full",
  "name": "裙子女生·竖版",
  "at": 1791554387219,
  "template": "全身竖构图……{{#头饰}}头饰：{{头饰}}；{{/头饰}}鞋子（必穿）：{{鞋子}}。……",
  "slots": [
    { "name": "头饰", "values": ["酒红色缎面蝴蝶结发夹别在耳侧"], "p": 0.5 },
    { "name": "鞋子", "values": ["白色细带玛丽珍鞋"] }
  ],
  "count": 50,
  "skipDup": true
}
```

**字段说明**

| 字段 | 用途 |
|---|---|
| `batch.template` | 模板文本（含 `{{占位符}}` 与条件块 `{{#名}}…{{/名}}`） |
| `batch.slots` | 占位符定义，`name` 不含花括号；可选字段 `p` = 出现概率（见下） |
| `batch.skipDup` | 跳过重复组合开关（有可选槽位时运行时忽略，见下） |
| `batch.count` | 张数 |
| `plan.v` | 计划格式版本；`2` 起 `combos` 里可能出现 `-1`（缺席标记） |
| `plan.status` | `idle` / `running` / `paused` / `done` |
| `plan.cursor` | 已完成张数（续跑从 `cursor` 继续） |
| `plan.usedCombos` | 已用组合，格式 `"服装索引\|场景索引\|动作索引"`；供"跳过重复"判定 |
| `plan.slotNames` | 冻结时的占位符名称顺序（与 `combos` 的下标一一对应） |
| `plan.combos` | 本批冻结的各槽下标表（保证「预览 = 实际生成」） |
| `plan.templateHash` | 模板 + 数组的哈希；与当前不一致 → 旧计划作废 |
| `plan.frozen` | 启动时冻结的生成参数快照 |
| `plan.results` | 每张的 `{idx, seed, w, h, secs}`；**只存元数据，不存图**（1 档） |

**为什么存 `usedCombos` 而不是存每张的完整提示词**：组合索引占用极小（3 个数字），且能精确判断重复。

### 占位符出现概率（后续加入）

槽位可选字段 `p`：该占位符在每张图里出现的概率。

| `p` | 含义 |
|---|---|
| 缺省 / `p >= 1` / 非数字 | **必选**（100%，字段不落盘） |
| `0 < p < 1` | 可选，按该概率出现 |

- 缺席用**独立下标通道**（`idxs = -1`）表示，**不能**用空字符串 ——
  `slotValues` 会 `filter(v => v !== '')` 把空串静默吞掉，导致概率失效
- 模板用**条件块** `{{#名}}…{{/名}}` 包住「标签 + 占位符」，
  缺席时整块删除；只替换成空串会留下 `眼镜：；` 这种空标签
- 抽签在**冻结时**决定（缺席作为隐藏维度参与抽样），所以 `plan` 仍可精确续跑
- 服务端 `sanitize` 是白名单重建，`batch.slots` 与模板 slots **两处**
  都要透传 `p`，否则每次保存都会被静默丢弃
- `p` 范围 `(0, 1]`，**禁止 0**

**去重何时被禁用**（`skipDup` 字段原样保留，只是运行时忽略）：

```
可用 ⟺ 模板实际引用的槽位里没有 0<p<1 的槽位
       且 ∏N ≤ 2^53-1（Number.isSafeInteger，混合进制索引的精确边界）
```

禁用时开关置灰 + 旁注原因 + 文案改「允许重复」，不报红也不拦截。
`p = 1` 与不写 `p` 等价，不禁用去重。

### 不重复抽样的实现（惰性 Fisher–Yates）

「跳过重复」的语义是**同一批内绝不重复**，且 `张数 ≤ 组合总数`。实现方式：

```js
LAZY_SAMPLER = { sig, total, cursor, at: Map, where: Map }
  · at    : 位置 → 值（稀疏，缺省即恒等）
  · where : 值 → 位置（稀疏）—— 按 used 重建时 O(1) 定位
  · 每抽一张做一次部分 Fisher–Yates：把 [cursor, total) 里的随机位置 j
    与边界位 cursor 交换，返回被换到 cursor 的那个值，然后 cursor++
  · 同一批内连续调用走 O(1) 快路径（sig 未变 && cursor === used.length）
  · 续跑 / 刷新后按 plan.usedCombos 回放重建，逐项走 samplerConsume，同样 O(1)
  · 只在 Map 里记录真正交换过的位置 → 内存 O(已抽张数)
```

**为什么不用「全量枚举 + 筛掉已用」**（早期实现，已废弃）：

| | 旧：全量枚举 | 新：惰性洗牌 |
|---|---|---|
| 单张耗时 | O(total) | O(1) |
| 单次预览（n 张） | **O(n × total)** | O(n) |
| 内存 | O(total) 个数组 + n 个 key 字符串 | O(n) |
| 100 万组合 × 10 张 | **2 700 ms** | 0.8 ms |
| 1139 万组合 × 10 张 | **42 700 ms** | 0.2 ms |
| 1 亿组合 × 30 张 | 不可用（页面假死） | 4.4 ms |

这段开销挂在**输入路径**上（`onSlotEdit` → `syncBatchLabels` → `renderComboPreview`），
即「每敲一个字符」都会触发，所以旧实现下百万级组合时输入框直接假死。

**索引编码**：线性索引 ↔ `"i|j|k"` 键为混合进制（槽 0 最快变化），
与旧实现的枚举顺序完全一致，因此磁盘上旧的 `plan.combos` / `plan.usedCombos`
在新实现下仍能正确复原。`total` 超出 `Number.MAX_SAFE_INTEGER`（2^53）时
线性索引不再可靠，退回「随机重试 64 次」法——该量级下碰撞概率可忽略。

> **后续修订**：下面这段原始决策已被推翻，保留是为了记录理由的演变。
> 现在去重**会**在两种情况下被自动禁用（见前文「去重何时被禁用」）：
> ① 存在概率槽位（去重会扭曲概率分布）；② `∏N` 超出 2^53（索引失真）。
> 禁用只是**运行时忽略**，`skipDup` 字段原样保留，且会在 UI 上明确置灰
> 并注明原因 —— 不是静默撤销。
>
> 原决策的理由是「不重复是用户显式勾选的保证，不应被性能策略静默撤销」。
> 这个理由对 ② 已不成立（索引失真是**正确性**问题，不是性能策略）；
> 对 ① 则是设计意图的改变：既然用户要概率，就接受重复的可能。

| **终端任务依赖 sd-server 存活** | 关掉 `serve.cmd` 窗口 → 任务失败 | 脚本启动前探活并明确提示；失败时不会静默产出空文件 |
| **保存目录需真实路径** | 浏览器只能拿到目录句柄，拿不到路径 | UI 无 `DIR.realPath` 时直接拦下并提示先设目录 |
| **jsdom 依赖受 `%TEMP%` 影响** | 沙箱/环境重定向 `%TEMP%` → 6 套 jsdom 测试全部报模块缺失 | 重装 `npm install jsdom --prefix %TEMP%\sdjsdom`；见 README |
